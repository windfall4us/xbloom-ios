# xBloom App v0.3.1 — 修复页面结构回归

v0.3.0 的页面基线是生产 **2.6.0**（`c4356839…`），而 2.6.0 有一个结构缺陷：
调整页重构时漏掉 `</div></section>`，把设置页、新增页、底部导航、全部弹窗都吞进了 `#detailView`。
`#detailView` 在豆仓页是 hidden，于是 App 里：首页没有底部四个按钮、设置空白、同步页无出口、整理点了没反应。

v0.3.1 把基线换到 **2.6.1**（`0088f57a…`，已修复），其余不变。

| 项 | v0.3.0 | v0.3.1 |
|---|---|---|
| 基线 | `c4356839`（2.6.0，带缺陷） | **`0088f57a`（2.6.1，已修）** |
| bundle | `1e5770b1` | **`5894b2f1`** |
| 结构校验 | 53 PASS | **56 PASS / 0 FAIL**（新增五视图同级断言） |
| App 版本 | 2.2.0 (22) | **2.2.1 (23)** |

新增的 3 条断言：五个视图 + 底部导航必须同一嵌套深度、底部导航不得在 `#detailView` 内、列表空状态存在。
这一条对 iOS 尤其重要——bundle 是从网页重基来的，网页结构错，App 一定错。
